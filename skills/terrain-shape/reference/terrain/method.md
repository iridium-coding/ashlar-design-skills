# The terrain method

1. **Measure the site.** Run the Ashlar survey for the project. The heights file covers the box plus at least 16 blocks horizontally. It records SOLID, surface without leaves, and top. SOLID can include logs or leaves. Verify that the top of every exact column reaches air and extend a short read before using it. The exact site read covers the box plus eight blocks horizontally, down through the deepest planned seal and up through air above all foliage. Use the world and coordinates in the site manifest. Use the site's block runs to distinguish trunks, solid bed, suspended water and the surface on the bed. Resolve non-natural blocks before designing over them.
2. **Shape one field.** Author a recipe with one datum and seed. Shape a rolling base with FBM or Hybrid through a CubicSpline. For a mountain, combine it with warped Ridged noise using Max. Cellular makes spires or basins. Use a belt (Centerline + belt_from_path) or sparse convolution across region borders. Plan the blend to measured terrain and scale its width with the relief (about 14 or more blocks for a 46-block difference). In the recipe evaluator thermal then padded hydraulic erosion run before the final edge blend, so erosion cannot erase the join. Optional fluvial erosion cuts drainage channels. Stamp interior pads at the build datum with shoulders, then hold shores where required. The outer ring must match the surveyed ground within one block.
3. **Materialise and run GATE A offline.** Derive slope, aspect, curvature, elevation and water-distance masks. Weight surface mixes, slant palettes and exposed strata. A changed column includes the terrain down to the lowest adjacent exposed face plus its seal (four blocks by default). Deeper geology stays in place. The site read identifies whole trees whose roots move and preserves trees rooted on unchanged ground. Include their actual reach and flowing-water reach in phase bounds and backups. See `reference/terrain/water.md` for wooded banks and retained liquid. Run the launcher's `field` command. Its draft recipe, expected surface (F6), report and renders go in `terrain/previews/`, separately from emitted `terrain/<element>.*` files. Stop on a failed check and fix the recipe or read extent. Preserve the verification report and token with the plan.
4. **Review and get design approval.** Inspect all five PNGs. Hillshade shows drainage, relief the silhouette, profile the transition to surveyed ground. Slope and eye-level views reveal bare walls, terraces and abrupt edges. Show dimensions, relief, cells changed, existing trees and reach, palette, kept/covered/added liquid, any separately approved drains, planting counts and phase sequence. Show the effects on routes, neighbours and water at the player's viewing position.
5. **Plan planting.** Hand the approved geometry to `terrain-ecology`. Preview custom trees and confirm any changes to the design. Match plants and materials to the existing biome. Keep grading in that biome. A biome-specific request follows the dedicated named-biome approval in `reference/terrain/palettes.md`.
6. **Emit and build.** Run `emit` with the next available phase number. Merge the generated plan rows into the joint project, or use its standalone plan. Retain module and commands files in the project. Put terrain, forms and flow before buildings, then custom trees, features and ground cover. Any approved biome change follows planting. Entities follow blockwork. Give the plan to `exec-ashlar build` for its own gate and complete rollback points before writing.
7. **Check from the ground.** Use a fresh heights file with `compare` on the expected surface. For seams use `seam --site POST_BUILD_F1 --from X Z --to X Z --outward DIR --max-step N` on actual ground. A positional heights file can screen straightforward edges, but ambiguous tree columns require the exact post-build read. Inspect disputed columns, both sides of a join and underwater faces. Use vertical slices and short facades, and ask for an in-game view on hero terrain. Offer `terrain-integrate` when a build needs a graded apron. Re-sculpt through the saved recipe and restore newest phases first on rollback.

`terrain-shape` owns the continuous landform. Hand recognisable landmark composition to `terrain-landmark` to combine two to four signature primitives. `terrain-ecology` owns planting and any named-biome decision, `terrain-integrate` owns grading around a footprint, and `exec-ashlar` owns the approved build.

Use `reference/terrain/toolkit-api.md` for the launcher, `reference/terrain/validation.md` for visual checks, and `reference/terrain/primitives.md` for landmark forms.
